# Persona review 11: the open-source legal expert

Laptop, 30 minutes, 2026-10-26. The repository at commit `31a4320` (the same as https://github.com/gijom33/limpide), `gh` for what only GitHub shows, the live site https://gijom33.github.io/limpide/ fetched with `curl` and driven with Playwright from a scratch folder. Nothing in the repository was changed; `npx license-checker` ran from the npx cache and `git status --short` was empty before and after.

This is a compliance read, not legal advice. Where a point turns on the law of a particular country, it is marked **lawyer to confirm**.

## First impression

"MIT, detected by GitHub, one copyright holder, a personal side project. Two runtime dependencies, both React. A web page, not a library, so the questions are: what ships to the visitor's browser, what the page sends to third parties, and what a company inherits if it forks. Every commit is co-authored by an AI agent and the README doesn't say so. Let's see whether the notices travel with the bundle and what that visit counter does."

## What they checked, in order

1. **The licence.** `LICENSE` is the standard MIT text, line 3: `Copyright (c) 2026 Guillaume Boillet`. `gh api repos/gijom33/limpide/license` → `{"name":"MIT","path":"LICENSE"}`; `package.json` line 18 `"license": "MIT"`; README lines 55–57 "[MIT](LICENSE) © Guillaume Boillet"; About splash (`src/ui/About.tsx` lines 99–105) "Free and open source under the MIT License" with a link to the source. Holder and year agree everywhere and match the git history (first commit 2026-10-21, all 218 commits authored by Guillaume Boillet). Consistent.
   - Coverage: MIT speaks of "this software and associated documentation files". The docs (`docs/`, `CONTEXT.md`), the Presets (`src/patch/presets.ts`, names plus a sentence of prose each) and the Demo's and Song's music (`src/demo/track.ts`, `src/demo/song.ts`, written as note strings in TypeScript) all live in the same repository and are most naturally read as covered. Nothing says so explicitly, and MIT is an odd fit for prose and music. Low risk, easy to make explicit.
2. **Dependency licences.** From `package-lock.json` (lockfileVersion 3, 111 entries; read with a short `node -e` over `packages[*].license`):

   | Scope | Licences (count) |
   | --- | --- |
   | Production (ships to the browser) | MIT 3 (`react` 19.3.1, `react-dom` 19.3.1, `scheduler` 0.28.0) |
   | Development (build and test only) | MIT 67, Apache-2.0 26, MPL-2.0 12, ISC 2, BSD-3-Clause 1 |

   Cross-check on what is actually installed (68 packages in `node_modules`): MIT 56, Apache-2.0 7, MPL-2.0 2, ISC 2, BSD-3-Clause 1. `npx license-checker --production --summary` → `MIT: 3, UNLICENSED: 1`; the UNLICENSED entry is `limpide@1.8.1` itself, which the tool reports that way because `package.json` line 19 is `"private": true`, not a real gap.
   - **Copyleft:** only `lightningcss` and its 11 platform binaries, MPL-2.0, a dev-only CSS tool pulled in by Vite. MPL-2.0 is file-level copyleft and applies to the MPL files if you distribute *them*; Limpide doesn't modify or ship them. No GPL, LGPL, AGPL, SSPL or "Commons Clause" anywhere.
   - **Unknown or missing:** none. Four packages carry `"license": "MIT"` but no LICENSE file in the tarball (`@polka/url`, `@rolldown/binding-darwin-arm64`, `sirv`, `stackback`), all dev-only. Irrelevant to the shipped page.
3. **What ships, and whether the notices ship with it.** The live bundle `assets/index-CzWN9CiI.js` (382,796 bytes) contains React 19.3.1 (`grep -o 'react.dev/errors'` matches, `19.3.1` matches) but `grep -ci 'license\|copyright'` finds exactly one line, Limpide's own About text. React's source carries `@license React … Copyright (c) Meta Platforms, Inc. and affiliates` (`node_modules/react-dom/cjs/react-dom-client.production.js` lines 1–8, which also embeds a Modernizr MIT notice); the production build strips it. `https://gijom33.github.io/limpide/LICENSE` → 404. So the site distributes React without React's copyright and permission notice, which is the one condition MIT imposes. See risk 1.
4. **Who owns the AI-written code, and is it stated.** `git log --format=%B | grep -i co-authored-by` → 184 × `Claude Opus 5.5`, 34 × `Claude Fable 5.1`. `grep -niE "claude|anthropic|\bAI\b|agent"` over `README.md`, `CONTEXT.md`, `docs/prd.md`, `docs/adr`, `docs/design-principles.md` → nothing. The trailers are honest; the README and LICENSE are silent.
   - What I'm confident of: the US Copyright Office's January 2025 report on AI and copyrightability (Part 2) takes the view that material generated by an AI system without sufficient human creative control isn't protected by copyright, while human selection, arrangement and modification can be. The repo shows a lot of human direction (ADRs "decided by the owner", issues, reviews), but how much of any given file is protectable is a fact question.
   - What I'd want a lawyer to confirm: what Anthropic's current terms say about ownership of outputs for the plan the owner uses (my recollection is that Anthropic's terms assign whatever rights it has in outputs to the user, but I haven't checked the version in force), and how EU or French law treats the same question.
   - Why it matters little to a *user* and a bit to the *owner*: if some of the code isn't copyrightable, a company can still use it (nobody can sue over it); the owner's copyright line and MIT grant simply cover less than they appear to. The real compliance worry with AI-written code is the opposite one: that it reproduces someone else's licensed code verbatim. `grep -rniE "adapted|ported from|stackoverflow|copied|borrowed|copyright|spdx" src e2e public` finds nothing but the About text; the code reads as purpose-built for this app (its own vocabulary from `CONTEXT.md` throughout). I didn't run a snippet-matching scanner; a company would.
5. **Third-party names and marks.** In the UI: "TempoPAD C16" (`src/ui/tips.ts` line 42, `src/midi/c16.ts` lines 52 and 80 to recognise the device by name), "Chrome", "Edge", "Safari", "iPhone", "iPad", "Apple" in compatibility messages (`src/ui/MidiPanel.tsx` lines 33–37, `src/ui/StartFailure.tsx` line 24); "Synido TempoPAD C16" in `docs/prd.md` line 18, `docs/adr/0004…md` line 5, `CONTEXT.md` line 216; README line 18 (Chrome, Edge, Safari, iPhone, iPad, Apple). "Serum-style" in a code comment only (`src/ui/modulationRing.tsx` line 71). "Ableton", Korg, Roland, Moog, Arturia, Novation etc.: none. No third-party logos: `public/` holds only Limpide's own mark (`favicon.svg`, a hand-drawn gradient path; two PNG renders of it). Every use is plain text, says what the product is or whether it works, and implies no endorsement. That's textbook nominative use. The C16's factory CC numbers in `src/midi/c16.ts` are facts needed for interoperability.
6. **The visit counter.** Injected only into production builds by `vite.config.ts` lines 22–34; line 30 hard-codes `data-goatcounter: 'https://gijom33.goatcounter.com/count'` and `src: 'https://gc.zgo.at/count.js'`. Live, with Playwright (Chromium, fresh context):

   ```
   GET  gc.zgo.at                https://gc.zgo.at/count.js
   POST gijom33.goatcounter.com  https://gijom33.goatcounter.com/count?p=%2Flimpide%2F&t=Limpide&s=1280&b=153&rnd=y0zjj
        headers: referer https://gijom33.github.io/, user-agent …, sec-ch-ua …
   cookies: []
   localStorage keys: [ 'limpide.current', 'limpide.overlays', 'limpide.theme' ]
   privacy text on page: false
   ```

   So: two requests to a third party (script, then count), carrying the path, the page title, screen width, a bot flag, the Referer and User-Agent headers and, as with every HTTP request, the visitor's IP address. No cookies, confirmed. Opened as `/?utm_source=linkedin#p=eyJjdXRvZmYiOjAuM30`, the count becomes `p=%2Flimpide%2F%3Futm_source%3Dlinkedin … q=%3Futm_source%3Dlinkedin`: the query string is sent, **the share link's `#p=` fragment is not** (fragments never leave the browser, and `src/ui/App.tsx` line 291 removes it after loading anyway).
   - The only privacy statement is README line 20, "no cookies and no personal data". A visitor never sees the README; the site itself says nothing (no footer, nothing in About). Under the GDPR an IP address is generally treated as personal data (CJEU, *Breyer*, C‑582/14), so "no personal data" is too absolute as a description of what the browser *sends*, even if GoatCounter, by its own account, doesn't store IPs. GitHub Pages also receives and logs visitor IPs, as any host does.
   - `localStorage` holds the current Patch, the Viewer overlays and the theme: functional storage for features the visitor uses, which the ePrivacy rules generally allow without consent as "strictly necessary". **Lawyer to confirm** for the EU.
   - Whether the owner, as a private individual running a non-commercial demo, is a "controller" with GDPR information duties at all, and whether GoatCounter's processing needs a consent banner: **lawyer to confirm**. My practical view: a cookieless, IP-not-stored counter generally doesn't call for a banner, but a short, visible privacy note costs nothing and removes the question.
   - No Subresource Integrity on the third-party script (`vite.config.ts` line 30 sets only `async` and `src`): `gc.zgo.at` can change what runs inside the page. Low risk, worth knowing.
7. **Contributions.** `gh api repos/gijom33/limpide/community/profile` → health 42; `contributing`, `code_of_conduct`, `issue_template`, `pull_request_template` all `null`. No CLA, no DCO, no `SECURITY.md`. GitHub's Terms of Service contain an "inbound = outbound" clause for contributions to a licensed repository, which gives an MIT project a baseline; many companies' policies still want a DCO sign-off on the project they contribute to, and a statement of the project's stance on AI-generated contributions given its own history. **Lawyer to confirm** whether the ToS clause is enough for the owner's purposes.
8. **Bundled assets, fonts, music.** No fonts are bundled or fetched: `src/styles.css` uses `system-ui, -apple-system, sans-serif` (line 58) and `ui-monospace` (lines 855, 1054). No images beyond the own logo; three screenshots of Limpide itself in `docs/issues/15-ui-polish/`. No audio samples: every sound is synthesised. The music is written out in `src/demo/track.ts` and `src/demo/song.ts`: an acid line, arpeggios, a wobble bass and stabs over Am–F–C–G (line 55 of `track.ts` calls it "the four chords of a great deal of modern dance music") and Cm–A♭–E♭–B♭. The About says "The Demo and the Song are originals" (`src/ui/About.tsx` line 98). I recognised no existing melody. Chord progressions are generally treated as not protectable on their own; **lawyer to confirm** if anyone ever claims otherwise.
9. **The share link.** `src/patch/serialize.ts` lines 42–58: the Patch's changed parameters, JSON in base64url, in the `#p=` fragment (`src/ui/PatchBar.tsx` line 90). Numbers and enumerated choices only (no name, no free text: `sanitizePatch`, lines 10–21, keeps only known numeric parameters and allowed choices). Nothing personal travels, the fragment isn't sent to any server (checked above), and malformed input is discarded. Clean.

## What is in order

- A standard, correctly placed MIT licence that GitHub detects, with the holder and year consistent across `LICENSE`, `package.json`, the README and the About splash.
- A tiny, entirely permissive production dependency set (React, MIT). Dev-only MPL-2.0 (`lightningcss`) is unmodified and not shipped. No unknown or missing licences.
- No bundled fonts, samples, stock images or third-party logos. The logo is original.
- Third-party names used only to describe compatibility, in plain text.
- The share link carries only sanitised synth parameters, in a fragment that never reaches a server.
- The counter sets no cookies, and a fork's development and test builds never load it.
- Honest AI attribution in every commit.

## The risks, ranked

1. **The live site ships React without React's licence notice.**
   - Where: the production bundle (`dist/assets/index-*.js`, live `assets/index-CzWN9CiI.js`); the build in `vite.config.ts`.
   - Why it matters: MIT's single condition is that the copyright and permission notice be included in copies; the minifier drops React's `@license` header, and nothing else on the site carries it. Any company that forks and deploys inherits the same gap. Trivial to fix, but it's the one thing a scanner flags.
   - Fix: emit third-party notices with the build and link them from the About splash ("Third-party licences"). Either keep legal comments in the bundle, or generate a `THIRD-PARTY-NOTICES.txt` (React, React DOM, scheduler, and the Modernizr notice inside react-dom) into `dist/`. Recent Vite versions have a build option that writes a licence file for bundled dependencies; check the docs for the Vite 8 option before relying on it.
   - Lawyer: no, this is standard practice.
2. **No privacy note on the site, and the README's claim is too absolute.**
   - Where: README line 20; nothing in `src/ui/About.tsx` or anywhere on the page; `vite.config.ts` lines 22–34.
   - Why it matters: a LinkedIn audience includes EU visitors. The page sends IP, User-Agent, Referer, path (including any query string) and screen width to GoatCounter, and stores three items in `localStorage`. Visitors are told nothing, and "no personal data" is hard to defend for a request that necessarily carries an IP address.
   - Fix: a short "Privacy" entry in the About credits (and the README) saying: visits are counted by GoatCounter, which receives the page address, referrer, browser and screen size and the IP address with each request and, per GoatCounter, doesn't store the IP or set cookies; GitHub Pages hosts the site and logs requests; settings and the current sound are kept in the browser's local storage and never leave it; link GoatCounter's and GitHub's privacy statements. Replace "no personal data" with "no cookies, and no personal data stored".
   - Lawyer: yes, for whether this is sufficient under GDPR/ePrivacy and whether any consent is needed.
3. **A fork that deploys sends its visitors to the owner's GoatCounter account.**
   - Where: `vite.config.ts` line 30 hard-codes `https://gijom33.goatcounter.com/count`; the plugin runs on every production build.
   - Why it matters: a company or person who forks and runs `npm run build` (the README's own instructions) publishes a site that reports its visitors to Guillaume's dashboard. That makes the owner a recipient of a third party's visitor data without either side knowing, and is the first thing a company's review of a fork would strip.
   - Fix: read the endpoint from an environment variable (e.g. `VITE_GOATCOUNTER`), set it only in `.github/workflows/deploy.yml`, and load nothing when it is unset; say so in the README's "Run it locally".
   - Lawyer: no.
4. **AI authorship isn't stated where users of the code look.**
   - Where: `README.md` (no mention), `LICENSE`; versus the 218 `Co-Authored-By: Claude` trailers.
   - Why it matters: many companies' open-source policies ask whether a project contains AI-generated code, both for provenance and because the copyright position of such code is unsettled. Finding it only in commit trailers looks like an omission, though it isn't one.
   - Fix: one paragraph in the README: written with Claude Code under the owner's direction (PRD, ADRs, issues, reviews in `docs/`); released under MIT to the extent of the owner's rights; no third-party code knowingly included.
   - Lawyer: yes, for the exact wording on ownership and for the provider's current terms on outputs.
5. **No contribution terms.**
   - Where: no `CONTRIBUTING.md`, no DCO, no CLA; community profile health 42.
   - Why it matters: a company contributor's legal team will ask under what terms the PR is accepted and whether the contributor may submit AI-generated code. Without a statement, it defaults to GitHub's ToS clause (lawyer to confirm). A CLA would be overkill for a project this size.
   - Fix: a short `CONTRIBUTING.md`: contributions are under MIT (inbound = outbound); sign off commits with the DCO (`git commit -s`); disclose AI assistance with a `Co-Authored-By` trailer as the project itself does; issues go to GitHub Issues. Optionally a `SECURITY.md` with a contact.
   - Lawyer: optional.
6. **Licence coverage of non-code content is implicit.**
   - Where: `LICENSE`; the Presets in `src/patch/presets.ts`, the music in `src/demo/`, prose in `docs/` and `CONTEXT.md`.
   - Why it matters: low. A teacher reusing the Preset texts or a musician reusing the Demo will wonder whether MIT covers them, and MIT is written for software.
   - Fix: one line in the README's "License" section: "Everything in this repository, including the docs, the Presets and the Demo's and Song's music, is under the MIT License."
   - Lawyer: no.
7. **The third-party counter script loads without integrity pinning.**
   - Where: `vite.config.ts` line 30.
   - Why it matters: low. Whoever controls `gc.zgo.at` can run code in the page. No credentials or personal data are present in the page to steal, so the impact is small.
   - Fix: pin a versioned script with an `integrity` attribute if GoatCounter publishes one, or self-host `count.js` in `public/`.
   - Lawyer: no.

## Would they

- **Approve use by a company (running the hosted site, or using the app internally): yes.** MIT, permissive dependencies only, no bundled third-party assets, nothing personal leaves the page beyond a cookieless counter. Condition for an EU employer's internal portal: ask for the privacy note (risk 2) first.
- **Approve a fork: yes, with two changes in the fork.** Add the third-party notices (risk 1) and remove or repoint the counter (risk 3) before deploying. Both are under an hour.
- **Approve a contribution: not yet.** The licence is fine, but without a `CONTRIBUTING.md` stating inbound terms and the AI-code policy (risks 4 and 5), a corporate contributor's policy would typically block the PR or require a one-off sign-off. Once those exist: yes.

2. No privacy note on the site; README line 20's "no personal data" is too absolute since every count sends IP, User-Agent, Referer and path to GoatCounter: add a Privacy entry to the About credits and soften the README (lawyer to confirm for the EU).
3. `vite.config.ts` line 30 hard-codes `gijom33.goatcounter.com`, so any fork that builds and deploys reports its visitors to the owner's account: read it from an env var set only in `.github/workflows/deploy.yml`.
