# Persona review 4: the AI expert

Laptop (1440 × 900, Chromium), 20 minutes, 2026-10-26. The site at https://gijom33.github.io/limpide/, then the repository as a visitor reads it on GitHub (README, `docs/`, `CONTEXT.md`, commit history, tests, Actions).

## First impression

"Polished dark synth UI, a welcome card with 'Play the Demo', a build hash in the corner that links to the exact commit. That's a nice touch; someone cares about traceability. Nothing on the page says how it was made, which is fine for a synth. I came for the process, so off to GitHub. The README is clean and product-first, but its 'How it's built' section is just the stack plus links to CONTEXT.md, ADRs and issues. No word about Claude Code, agents or AI Hero. If the LinkedIn post hadn't told me, I wouldn't know from the README."

## What they tried, in order

1. **The site.** It loads to a welcome card over the instrument; About shows "Version 1.8.1 · build 2ba9f3a" with a link to that commit, and "Made by Guillaume Boillet". No AI credit anywhere on the site. That's fine, but the post's claim has to be backed up somewhere else.
2. **README.** Clear pitch, run-locally table with three test commands, "How it's built" linking `CONTEXT.md`, `docs/adr`, `docs/issues`. It doesn't link `docs/prd.md`, `docs/inbox.md` or `docs/design-principles.md`, and doesn't name the method or the agent. No screenshot either, although issue 25's release checklist says "README screenshots refreshed when the look changed".
3. **Searched the repo for "Claude", "agent", "AI Hero".** The only hits are in `docs/issues/42-reviews.md` (the review I'm part of). There's no `CLAUDE.md` or `AGENTS.md`, no skills folder, no prompts. Only `.claude/launch.json` is tracked.
4. **Commit history** (`git log`, 206 commits from 2026-10-21 20:28 to 2026-10-26). Every single commit carries a `Co-Authored-By: Claude …` trailer (172 Opus 5.5, 34 Fable 5.1). *That* is the proof I wanted, and it's honest. The first commit is "docs: glossary, ADRs and PRD for SynthView", then "feat: vertical slice … (ticket 01)" fifteen minutes later. PRD first, then the code, which is the AI Hero order. Six days, ~35 commits a day: only plausible with an agent, and it reads as one.
5. **Commit message style.** The first 38 are conventional commits (`feat:`, `fix:`, `docs:`). After that it switches to prose: "Issue 44 built: one header across the layouts. One order everywhere (the Wordmark and the Patch; Demo, Song, Hold; …". 22 subject lines are over 150 characters, the longest 498. On GitHub's commit list they're all cut off with "…". The content is good, unusually precise even (measurements, before/after timings), but the whole message is crammed into the subject line. That's the one place where it reads like an agent wrote it and nobody trimmed it.
6. **PRD** (`docs/prd.md`). 83 user stories, implementation decisions, deep modules with interfaces, testing seams, out-of-scope. Textbook AI Hero. Then line 11: "Limpide (formerly Limpide) is a browser-based subtractive synthesizer". That's a find-and-replace rename (the app was SynthView) that nobody re-read. Stories are numbered 1–49, then "Look and feel" 69–83, then MIDI 50–61 and Patches 62–68: the new stories were inserted mid-document. Out of Scope still says "Spectrogram and explanatory tooltips, which are next after v1", yet tooltips shipped on day one (`723fa1d`, `e2e/tooltips.spec.ts`). Testing Decisions promises "one Playwright smoke test"; `e2e/` has 38 spec files.
7. **Issues** (`docs/issues/01` to `44`). Each has "What to build", "Blocked by", "Status" and a checklist. Issue 44 is the best thing in the repo for my purpose: measured current state, a proposal, "Decisions open … decided by the owner on 2026-10-26, all four as proposed", then a "Built" checklist with the test that covers it, and an unchecked "Tried on a real foldable and a laptop". That shows the human in the loop. Issue 40 says "to grill first", issue 41 is "a diagnosis first". The skills show up in the vocabulary, though they're never named as skills.
8. **Issue 18 (prototypes)** says the prototype is "kept, never merged, on branch `prototype/2.0-look`". That branch isn't on GitHub (`main` is the only remote branch), so a visitor can't follow the link.
9. **ADRs** (`docs/adr/0001`–`0009`). Short, with "Considered Options" and "Consequences". ADR-0005 (monophonic by design) is kept and marked superseded by ADR-0007. That's the right way to do it, and it shows a decision being reversed by the owner ("Rejected by the user: polyphony for playing is wanted"). But ADR-0007's Consequences contradict each other: one bullet says the Display panel's "Viewers follow" defaults to All, summing every Voice at the Amp Tap; the next says "The Amp Tap shows the newest Voice too, not the sum." The code (`src/viewers/viewerState.ts`, `tapSource: 'all'`) agrees with the first.
10. **CONTEXT.md glossary.** Good, opinionated `_Avoid_:` lines, and the code uses the words (`envelopeLevel`, "the Maths Layer: Resonance as Q" in test names). Two slips: "Preset" lists six (Init, Bass, Lead, Pluck, Pad, Wobble) while `src/patch/presets.ts` now has about a hundred in 14 groups; "Share link" has a second `_Avoid_: Factory patch, template` line that belongs to Preset.
11. **The inbox** (`docs/inbox.md`). Empty Bugs/Ideas, with a dated triage log moving each line to a numbered issue. It shows the loop running and isn't linked from the README.
12. **Code and tests.** `src/` is split by domain (`patch`, `modulation`, `engine`, `midi`, `viewers`, `ui`), with pure modules separate from React as the PRD says. I read `src/modulation/envelope.ts` and `src/patch/taper.test.ts`: small, commented with the *why* ("ADR-0003: one model for picture and sound"), and tests that assert behaviour through the public interface ("puts the geometric mean at the middle, so every octave gets equal travel"). Roughly 8,500 lines of source to 8,500 of tests. I ran `npm run test:unit`: 44 files, 363 tests, all green in 5 s. 128 of the 141 commits that touch source also touch tests. `src/ui/App.tsx` is 963 lines, the one spot that looks like it grew by accretion.
13. **CI** (`.github/workflows/deploy.yml`, `gh run list`). Every recent run is green, 30–60 s. But the job runs only `npm run test:unit` and the build. The engine test in real Chromium and the 38 Playwright specs never run in CI, though the README says "Every push to `main` is tested". There are no git tags or GitHub Releases either, although `docs/issues/25-releases.md` logs versions 1.2.0 to 1.8.1.

## What worked

- The process artifacts are real and connected: PRD → numbered issues with checklists → ADRs that cite each other → glossary words used verbatim in code and test names → an inbox that triages into issues. This is the AI Hero shape, done consistently over 44 issues, not a one-off demo.
- The human decisions are visible: "decided by the owner", "rejected by the user", "tried by the owner on a real phone", "look B chosen on 2026-10-24". That's what makes "built with AI" believable *and* creditable to the author.
- Co-author trailers on every commit: honest, checkable attribution.
- Test discipline is real, not decorative: behavioural tests, 1:1 test-to-code volume, tests in the same commit as the code, flaky timing tests diagnosed and fixed with numbers in the inbox log.
- The build hash on the About card linking to the commit.

## Where they got stuck or gave up

- Finding the AI part at all: nothing in the README or the site says "Claude Code" or "AI Hero". I only knew to look at commit trailers because I know the convention. A non-expert who clicks through from LinkedIn wouldn't find it.
- No `CLAUDE.md`/agent instructions or skills config in the repo. For an AI practitioner, *how the agent was steered* is the most interesting part, and it isn't there.
- Docs drift that a careful reader trips on within minutes: "Limpide (formerly Limpide)", the self-contradicting ADR-0007 bullet, the six-Preset glossary entry, the stale Out of Scope and Testing Decisions in the PRD. Each one is small. Together they're exactly what a sceptic quotes as "unreviewed AI output".
- Commit subjects too long to read on GitHub; I gave up reading the history there and used `git log` locally instead.
- The prototype branch referenced in issue 18 doesn't exist on GitHub.

## Would they…

- **Like the post:** yes. The app looks finished and the repo backs up the process with real artifacts.
- **Share it:** yes, with a caveat. I'd share it as an example of the PRD → issues → ADR workflow in practice, but I'd want a link that lands on the process, not on a README that doesn't mention it.
- **Come back:** yes, to read the issues and ADRs more slowly. Issue 44 and ADR-0007 are good teaching examples of agent work with a human deciding.
- **Recommend working this way:** yes. The repo shows the method scales to 200 commits without falling apart, and the drift it does have is the kind a periodic "docs vs code" review pass would catch. I'd add that pass to the method.

## Three findings, ranked

1. `README.md` never says how Limpide was built: no mention of Claude Code, the AI Hero method or the PRD, and "How it's built" links neither `docs/prd.md` nor `docs/inbox.md` nor `docs/design-principles.md`; the only trace is the `Co-Authored-By: Claude` trailer on all 206 commits, and no `CLAUDE.md`/skills are in the repo. Add a short "How this was built" section (PRD → issues → ADRs → inbox, agent and skills named, what the owner decided).
2. Docs drift a visitor spots in minutes: `docs/prd.md` line 11 "Limpide (formerly Limpide)" (rename artifact), PRD Out of Scope still lists "explanatory tooltips" (shipped day one) and Testing Decisions "one Playwright smoke test" (38 specs); `docs/adr/0007-…` Consequences say the Amp Tap sums every Voice by default and, next bullet, "shows the newest Voice too, not the sum" (code: `tapSource: 'all'`); `CONTEXT.md` Preset names six Presets (there are ~100 in 14 groups) and Share link carries Preset's stray `_Avoid_` line.
3. `.github/workflows/deploy.yml` runs only `npm run test:unit` and the build, so the Chromium engine test and the 38 Playwright specs never run in CI although the README says "Every push to `main` is tested"; the history is also hard to read on GitHub (22 commit subjects over 150 characters, up to 498, after a switch from conventional commits), there are no tags or Releases for versions 1.2.0–1.8.1, and `docs/issues/18-prototypes.md` points to a `prototype/2.0-look` branch that was never pushed.
