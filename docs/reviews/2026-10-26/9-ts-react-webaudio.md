# Persona review 9: the TypeScript, React and Web Audio expert

Laptop (Apple M2, 1440 × 900, Chromium and WebKit through Playwright), 30 minutes, 2026-10-26. The code at `2f354e8` (`src/`, `tsconfig.json`, `vite.config.ts`, ADRs 0001–0003), a production build, the engine test suite, and the live site at https://gijom33.github.io/limpide/ measured with Playwright. The scripts and their raw output are in the reviewer's work folder (`measure.cjs`, `profile.cjs`, `browsers.cjs`, `knobdrag.cjs`, `demo-throttled.cjs`). No tracked file was changed.

## First impression

"Vite, React 19, TypeScript 7 with `strict` on, no state library, no UI kit, two runtime dependencies. `src/` is split by domain, and the engine is one 764-line file of plain functions over native nodes, with a comment on almost every block saying *why*. Someone who knows Web Audio wrote the comments: 'an oscillator cannot be reset', 'a DynamicsCompressorNode was rejected: it adds make-up gain'. Then `App.tsx` at 963 lines with 18 effects, and I know where the bodies are buried."

## What they tried, in order

1. **Type strictness, by grep** (non-test `src/`). `strict`, `noUnusedLocals`, `noUnusedParameters` on (`tsconfig.json:7-9`); `noUncheckedIndexedAccess` off. **0** `any`, **0** `@ts-ignore`/`@ts-expect-error`. About **33** `as` casts and **34** non-null `!`. Most are DOM boilerplate (`e.target as Node` in outside-click handlers, `ref.current!` inside effects) and are fine. The worst:
   - `src/ui/App.tsx:503`, `access as unknown as MidiAccessLike`. A double cast that turns the type checker off where the code meets the browser.
   - `src/ui/App.tsx:465-466`, `getAttribute('data-learn')!.split(':')` then `{ kind, id } as Target`: a string from the DOM cast straight to a discriminated union, with no check.
   - `src/ui/App.tsx:406`, `patchRef.current[id] as never`, which defeats `indexOf`'s type.
   - `src/midi/inputs.ts:33` and `:54` cast `Event` to hand-written shapes, although lib.dom has `MIDIMessageEvent` and `MIDIConnectionEvent`.
   - `src/ui/App.tsx:174`, `PRESETS.find(...)!`. It's OK because `src/demo/track.test.ts` checks every part's Preset exists.
2. **Lint.** `src/ui/App.tsx:286`, `:353` and `src/ui/SectionStrip.tsx:135` carry `// eslint-disable-line react-hooks/exhaustive-deps`, but there is no ESLint in `package.json` or the repo. The disables silence a linter that never runs, so nothing checks hook dependencies anywhere else.
3. **Build.** `npm run build` (tsc + Vite 8) takes 2.6 s. One chunk: `index-*.js` 383 kB (122 kB gzip), CSS 41 kB (8.8 kB gzip). React DOM is about half of that, and the rest is app code plus about 100 Presets and the tips text. Fine for what it does, no code splitting needed. `index.html` has `lang="en"` and relative icon paths, but no `<meta name="description">` or `<noscript>`, which matters for a link shared on LinkedIn.
4. **Engine tests.** `npm run test:engine`: 185 tests in real Chromium, all green in 54 s. They render audio and measure it (`src/test/measure.ts`), which is rare and good.
5. **Read the engine** (`src/engine/synthEngine.ts`) and the Envelope model (`src/modulation/envelope.ts`). Notes below.
6. **Read the React side**: `App.tsx`, `TapViewers.tsx`, `modulationRing.tsx`, `LfoPlot.tsx`, `renderLoop.ts`, the Viewers in `src/viewers/`.
7. **Live site, frame cost** (Chromium 1440 × 900, every `requestAnimationFrame` callback timed with an init script):

   | State | Draw time per frame (median) | Frame rate |
   |---|---|---|
   | Idle, after load | 3.7 ms | 60 fps |
   | One Note held 5 s | 3.7 ms | 60 fps |
   | Right after 600 quick Notes | **31.5 ms** | **29 fps** |
   | 30 s later, silent, nothing touched | **29.7 ms** | **31 fps** |
   | Demo, 3–8 s in | 3.5 ms | 60 fps |
   | Demo, 28–33 s in | **12.3 ms** | **35 fps** |
   | Demo, 28–33 s in, CPU throttled 4× | **62.9 ms** | **6.6 fps** |

   A CPU profile of 3 s after 300 Notes, on the dev server so names aren't minified, puts **1.6 s of the 3 s in `envelopeLevel`**, and with `modulationAt`, `glideFrequency` and `trackedNoteAt` about 2 s. The Viewers' own canvas work (`columnPeaks`, `spectrumOutline`, `cycleLockOffset`) is under 130 ms. GC is 37 ms, so allocation isn't the problem.
8. **Live site, memory** (heap after forced GC): 3.9 MB before, 5.3 MB after 600 Notes, 5.2 MB 30 s later, 7.2 MB during the Demo. No leak: the engine builds every node once.
9. **Storage refused.** I made `window.localStorage` throw `SecurityError`, as Chrome and Safari do when a person blocks site data. **The page is blank**: `#root` has no children, and the uncaught error is "The operation is insecure."
10. **MIDI permission.** `navigator.requestMIDIAccess()` is called 0.7 s after load with `userActivation.hasBeenActive === false`. `navigator.permissions.query({name:'midi'})` reads `"prompt"` (headless Chromium rejects it with `NotAllowedError`). Since Chrome 124 all Web MIDI access is behind a permission, so a desktop Chrome visitor gets a "use your MIDI devices" prompt before they've touched anything. I didn't see the prompt itself, because headless has no browser UI.
11. **WebKit (Safari's engine).** Load, unlock and a held Note: `cancelAndHoldAtTime` exists, the Amp Scope reads −15 dB, no page errors. Firefox wasn't tested: no Firefox build is installed for Playwright here.
12. **Knob drag.** 120 pointer moves on Cutoff, from a capture listener to the next task: median 5.9 ms, max 9.4 ms per move. That's the handler plus a full `App` re-render. Fine on an M2. At 4× slower it would be around 24 ms, more than a frame (estimated, not measured).

## What is good

- **ADR-0002 is done properly.** One `requestAnimationFrame` loop (`src/viewers/renderLoop.ts`) and canvases mounted once (`TapViewers.tsx:34-49`). The settings reach the Viewers through a stable getter over a ref (`App.tsx:546-548`), so changing the overlays, cycles or Freeze never remounts a Viewer. The modulation rings and LFO plots write SVG attributes straight from the loop (`modulationRing.tsx:91-114`, `LfoPlot.tsx:31-43`) and never touch React state. That's how it should be done.
- **No node churn, no leaks.** `MAX_VOICES` Voices are built once (`synthEngine.ts:488`) and every source starts once. Notes only schedule automation, so nothing is created per Note. The one place nodes are replaced, the LFO retrigger, stops the old oscillator at `t` and disconnects it in `onended` (`synthEngine.ts:499-517`). The heap measurements agree: no growth across 600 Notes.
- **Click-free Envelopes, by construction.** Every Gate change starts with `cancelAndHoldAtTime` and then `setTargetAtTime` (`envelope.ts:50-58`), so a retrigger or an early release starts from the level the param actually has. The same function drives the picture (`envelopeLevel`), which is ADR-0003 done right: you can't draw one curve and play another. Lifting `cancelAndHold` into an `AutomationStep` union (`envelope.ts:17-19`) makes the schedule testable as data. Nice.
- **Web Audio knowledge shows.** The PWM pulse is a saw minus a delayed copy, scaled to the exact series (`synthEngine.ts:183-204`, `:371-374`). LFO PeriodicWaves use `disableNormalization` so the square sits at exactly ±1 (`:160-175`). The safety limiter is a 4× oversampled WaveShaper after the Taps, with the reason the compressor was rejected written down (`:451-459`). Envelope, Velocity and Key Track reach the Filter through `ConstantSource` → gain → `detune`, so the Amount knobs act mid-Note (`:290-319`). Per-Voice noise starts at offsets, so a chord's noise isn't one noise, louder (`:322-323`).
- **Safari care.** `resume()` is called synchronously in the gesture (`src/app/unlockAudio.ts:29-34`). `navigator.audioSession.type = 'playback'` handles the iPhone silent switch (`:51-55`). There's one AudioContext as a singleton, because React may run initialisers twice (`src/app/session.ts:18-24`).
- **Types are honest where it matters.** Zero `any`. Small `…Like` interfaces (`MidiAccessLike`, `UnlockableContext`) let tests stand in for browser APIs. The `SynthEngine` interface (`synthEngine.ts:48-80`) is a real seam, documented per method.
- **Error handling is mostly deliberate.** `safeStorage` (`App.tsx:117-123`), `loadOverlays`/`saveOverlays` and `loadTheme` all try/catch. Garbled storage "behaves as empty and never throws" (`src/patch/library.ts:14`). A refused MIDI request shows a "denied" state (`App.tsx:525`).
- **Markup.** Knobs are `role="slider"` with `aria-valuetext` (`paramControl.tsx:40-46`). About is a native `<dialog>` opened with `showModal()` (`About.tsx:35-41`), stages are `<section aria-label>` with `<h2>`, and Viewers are `<figure>`s.

## What they would ask to change

1. **The Modulation model is O(history) per query, and the Timeline queries it once per pixel column per frame.** `envelopeLevel` (`src/modulation/envelope.ts:37-44`) replays every Gate event from the start of the 30 s history on every call. `modulationAt` (`synthEngine.ts:620-648`) does that twice, loops over `ampEvents` twice more (`:627`, `:630`), and runs `glideFrequency` over all pitches (`:633`). `trackedNoteAt` allocates a new array of all pitches each call (`:602-603`). `createTimeline` calls it for every column (`src/viewers/timeline.ts:54`, about 500 columns), and each modulation ring calls it once more per frame. History is kept for `MODEL_SECONDS = 30` (`synthEngine.ts:133`), up to 4,096 events, and `trim` runs only when a new event arrives (`:550-553`), so the cost stays after the playing stops (row 4 of the table above). Fix: cache the level at each event's start when it's appended, so a query is a binary search plus one `levelWithin`. Or walk the columns forward in one pass, since they're in time order. Either brings it back to O(columns).
2. **Storage access outside the guard blanks the page.** `src/main.tsx:7` (`migrateStorage(localStorage)`) runs before React mounts, and `App.tsx:534` and `:536` pass the global `localStorage`. In all three, the property read happens *before* the try/catch inside the callee, and there's no error boundary. Pass `safeStorage()` everywhere, which `App.tsx:116` already wrote for exactly this case, and add a top-level error boundary with a "reload" message.
3. **Ask for MIDI on a gesture, not at load** (`App.tsx:495-531`). Call `requestMIDIAccess()` when the person opens the MIDI panel, or check `navigator.permissions.query({ name: 'midi' })` first and connect at load only when it's already `"granted"`. The `MidiState` already has `pending`, which fits.
4. **Firefox (suspicion, not tested).** `cancelAndHoldAtTime` (`synthEngine.ts:217`, `:395`, `:400`) is, as far as I know, still missing from Firefox (MDN lists it unsupported, Mozilla bug 1308431). If so, the first `noteOn` throws a `TypeError` inside `setPitch`, before the Gate is scheduled, so the page draws but never sounds. Run the smoke spec once in Playwright's Firefox. If confirmed, either feature-detect and fall back (`cancelScheduledValues` plus `setValueAtTime` at the model's own `envelopeLevel(t)`, which the code can already compute), or say "Chrome, Edge, Safari" on the page.
5. **`App.tsx` should be split.** 963 lines with 13 `useState`, 18 `useEffect`, 12 `useRef`, 7 `useMemo`, and 14 "latest value" ref mirrors (`patchRef.current = patch`, `octaveRef`, `heldRef`, `stopDemoRef`, `pressHoldRef`…). The mirrors work, but they are hand-rolled `useEffectEvent`. The natural hooks are already visible in the comments: `useDemo` (`:142-206`, `:240-286`), `useSong` (`:207-238`), `useHoldRhythm` (`:317-349`), `useMidi` + MIDI Learn (`:355-531`) and `useComputerKeyboard` (`:577-611`). Two effects run on data that should be events: `App.tsx:351-353` stops the Song from an effect on `heldNotes`, and `:327-329` notifies `holdTaps` the same way. Each is one extra render after the fact.
6. **Every MIDI message and every knob move re-renders the whole tree.** `setActivity(describeMessage(m))` on every message (`App.tsx:515`), and `setPatch` per move, with no `React.memo` anywhere in `src/ui`. Measured at about 6 ms per pointer move on an M2. A controller sweeping a CC sends about 100 messages a second. Memoise the stage blocks on their slice of the Patch, or put `activity` in a small external store read by the MIDI panel alone (`useSyncExternalStore`, already used for Mappings at `:369`).
7. **The render loop dies on the first exception.** `renderLoop.ts:8-11`: if any `draw()` throws, `requestAnimationFrame(tick)` is never called again. And because `frame` stays non-zero, `addToRenderLoop` never restarts it (`:16`). Every Viewer would freeze silently for the rest of the visit. Wrap each draw in try/catch, or reschedule before drawing.
8. **Viewers draw when nobody can see them.** No `IntersectionObserver` or visibility check, so the phone layout's hidden sections still read analysers and compute every frame. On a laptop it doesn't matter (3.7 ms idle). On a phone it is battery. Suspicion: not measured on a device.
9. **Per-frame style reads.** `cssVar` calls `getComputedStyle` 4–9 times per canvas per frame (`scope.ts:59-130`, `spectrum.ts:96-226`, `timeline.ts:37-110`). It's cheap while styles are clean, but it's work for nothing: read the theme's colours once per theme change.
10. **Types.** Turn on `noUncheckedIndexedAccess`. Replace the `as unknown as MidiAccessLike` (`App.tsx:503`) with a structural fix or a typed adapter. Parse `data-learn` into a `Target` with a guard (`App.tsx:465-466`). Use `MIDIMessageEvent` in `inputs.ts:33`. Add ESLint with `react-hooks`, or delete the three disable comments.
11. **Smaller ones.** `applyPatch` (`synthEngine.ts:696-733`) re-schedules about 25 params on all 8 Voices for every knob move. In `setWave` (`:372`), a pulse recomputes a 256-Harmonic series per Voice per move. `patchChanged` stringifies two Patches every render (`App.tsx:140`). `getAudioSession` builds the AudioContext inside a `useState` initialiser with no try/catch (`session.ts:26`), so a constructor failure would also blank the page (suspicion: I found no browser that throws there today).

## Would they…

- **Approve the pull request:** not as is. Request changes on two things: the Timeline's O(columns × history) cost, which takes the Demo to 35 fps on an M2 and 6.6 fps throttled after 30 s, and the unguarded `localStorage` reads that blank the page. Both are small, local fixes. The rest is comments, not blockers.
- **Hire the author:** yes. The engine shows real Web Audio understanding: automation that starts from the held value, a node graph built once, PWM from a delayed saw, and Taps as side branches. The tests measure rendered audio. The weaknesses (one oversized component, no lint, a hot loop nobody profiled with a long history) are what you'd expect from someone strong on the domain who hasn't had a senior React reviewer yet.
- **Reuse a module:** yes. `src/modulation/envelope.ts` (the model and its automation schedule are one source of truth) and `src/app/unlockAudio.ts` are small, tested and dependency-free. `synthEngine.ts` too, once the history queries are made incremental. `App.tsx`: no.

## Three findings, ranked

1. The Timeline replays the whole Modulation history for every pixel column, every frame: `envelopeLevel` (`src/modulation/envelope.ts:37`) and `modulationAt` (`src/engine/synthEngine.ts:620`) are O(30 s of Gate events), called about 500× per frame from `src/viewers/timeline.ts:54`, and `trim` (`synthEngine.ts:550`) only runs on new events. Measured on the live site: draw time 3.7 → 31 ms per frame after 600 Notes, staying there in silence, and the Demo at 30 s runs at 35 fps on an M2 and 6.6 fps with 4× CPU throttling. Cache each event's starting level and binary-search, or sweep the columns once.
2. If the browser refuses site storage, the page renders nothing: `src/main.tsx:7` and `src/ui/App.tsx:534`/`:536` read the global `localStorage` outside any try/catch (the guarded `safeStorage()` at `App.tsx:116` isn't used there) and there's no error boundary. Measured: with `localStorage` throwing `SecurityError`, `#root` is empty.
3. MIDI permission is requested at page load, without a gesture (`src/ui/App.tsx:500`). Measured: called 0.7 s after load, permission state `"prompt"`, so desktop Chrome visitors get a MIDI permission prompt before touching anything. Ask when the MIDI panel opens, or connect at load only if `permissions.query({name:'midi'})` is already `"granted"`. (Also check Firefox, where `cancelAndHoldAtTime` is thought missing and Notes may not sound at all: `synthEngine.ts:217`, `:395`. Untested.)
